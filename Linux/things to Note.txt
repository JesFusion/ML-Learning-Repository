{

    chmod (Change Mode):
    
    This command changes who can do what to a file. We have two ways to speak to the bouncer:
    
    1. Numeric (Octal):
    chmod (Change Mode) Permissions numbers:

    - Read (r) = 4
    - Write (w) = 2
    - Execute (x) = 1
    - No Permission = 0

    You sum these up for each of the three groups: User (Owner), Group, and Others.

    a. 755:

    User: 4+2+1 = 7 (Read + Write + Execute). You can do anything.

    Group: 4+0+1 = 5 (Read + Execute). Colleagues can run your script but not break it.

    Others: 4+0+1 = 5 (Read + Execute). The public can run it but not break it.
    
    ==> chmod 755 {filename}

    b. 600:

    User: 4+2 = 6 (Read + Write).

    Group/Others: 0. This is for SSH keys or secrets (.env files). No one else can even look at them.

    ==> chmod 600 {filename}




    2. Symbolic:
    - People:
    u = user
    g = group
    o = others

    - Abilities
    r = read
    w = write
    x = execute


    Examples:
    how to give only user permission to execute:
    ==> chmod u+x {filename}
    
    remove user's ability to execute:
    ==> chmod u-x {filename}

    give group ability to write:
    ==> chmod g+w {filename}

    revoke ability to read from others:
    ==> chmod o-r {filename}

    give everyone ability to read:
    ==> chmod +r {filename}
    
    give everyone ability to execute:
    ==> chmod +x {filename}

{
    htop mappings:

    Memorize these mappings:

    - Instead of F3 (Search): Press / (Forward Slash).

    Why: This is the universal search key in Linux (vim, less, man pages).


    - Instead of F4 (Filter): Press \ (Backslash).

    Why: It allows you to only see processes matching a string (e.g., "python").

    
    - Instead of F5 (Tree View): Press t.

    Why: Toggles between a flat list and a parent-child tree (essential for seeing which process spawned which).

    
    - Instead of F6 (Sort): Press > or ..

    Why: This lets you pick what to sort by (CPU, MEM, etc.).

    
    - Instead of F9 (Kill): Press k.

    Why: Opens the kill menu. Use this to terminate runaway Python scripts.

    
    - Instead of F10 (Quit): Press q.

    Why: Universal quit command.
},

{
    Commonly used process signals in Linux:


    1. SIGTERM (Termination Signal):

    Tells the program to stop, but gives it a chance to clean up (close database connections, save logs) before it dies.

    When to use it: ALWAYS try this first. It is the default in htop.

    
    
    2. SIGKILL (Kill Signal):

    The Kernel instantly removes the process from memory. The process has zero chance to save data or close files.

    When to use it: Only when a process is "hung" or "zombie" and refuses to listen to SIGTERM.

    Warning: If you use this on a database (like Postgres) or a training run, you will corrupt your data.


    3. SIGINT (Interrupt):

    This is exactly what happens when you press Ctrl+C in your terminal. It usually kills the script, but a smart Python script can "catch" this signal and do something else (like print "Exiting..." first).



    4. SIGHUP (Hang Up):

    Originally used when a phone line hung up. Today, we use it to tell background services (like Nginx or Docker) to reload their configuration files without actually stopping the server.

    Pro Tip: If you change a config file, don't restart the server; send it a SIGHUP.



    5. SIGSEGV (Segmentation Violation):

    This is the specific signal that caused your onboard keyboard to crash earlier. It means the program tried to access memory it wasn't allowed to touch.
